# Candidate tenant schema, generated from the `crims` database

**Not wired in.** The directory name starts with `_`, which `TenantRunner` rejects as an app name, so nothing can
apply it by accident. It exists so the tenant `orm` and `mdm` structure can be reviewed before it replaces or sits
beside `db/tenant_migrations/orm/0001`.

`orm.up.sql` then `mdm.up.sql` are generated by `scripts/gen-tenant-ddl.py` from `pg_dump -s` of `crims`. Schema only,
no data. Do not edit them: change the generator and regenerate (`REPORT.txt` lists everything the generator removed).

## What the generator changes, and why
| Change | Count | Reason |
|---|---|---|
| Row-level security removed (`ENABLE`/`FORCE ROW LEVEL SECURITY`, `CREATE POLICY`) | 967 statements, 976 policies | One tenant per database (ADR-042). The policies key on `app.current_tenant`, which the tenant router never sets, so keeping `FORCE` would make every table read as empty. |
| FK `orm.fund_order_settlement -> cash_flow.settlement` removed | 1 | `cash_flow` is not part of a tenant database. |
| psql meta-commands (`\restrict`) removed | 2 | pg_dump 18 emits them; they are not SQL. |
| `CREATE SCHEMA IF NOT EXISTS`, `uuid-ossp` created first | | The only extension the two schemas use (`uuid_generate_*`; the rest is core `gen_random_uuid()`). |

## Order, and why mdm is separate
`mdm` refers to `orm` (18 foreign keys) and `orm.account` refers back to `mdm.party`. So `orm.up.sql` never refers to
`mdm`; the one reference from `orm` into `mdm` is added at the end of `mdm.up.sql`. Apply `orm`, then `mdm`.

## Fidelity (checked against `crims` on an empty scratch database)
Tables 80 + 441, indexes 2,120, columns 8,002 (identical column by column, including defaults), functions 7
(identical bodies), triggers 2, primary/unique/foreign/check constraints identical except: the removed `cash_flow`
FK, and one foreign key on `orm.fix_alert` whose auto-generated name differs (same columns, same target, same
`ON DELETE CASCADE`), a `pg_dump` artefact of a foreign key declared on a partitioned table. NOT NULL constraints
were not compared (PG18 stores them as constraint rows, PG16 does not).

## What is not here
Data (reference data such as `mdm.calendar_day` is seeded separately, later), the `tenant_id` CHECK, grants, and the
wiring: provisioning takes one `App` today and would need an ordered list (`orm`, `mdm`).
